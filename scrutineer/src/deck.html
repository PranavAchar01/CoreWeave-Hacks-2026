Scrutineer is an agent that rebuilds its own harness, and we draw that harness as a race car so you can watch it change. We built it here at CoreWeave Hacks: Agent Loops, a whole weekend about the loop. It starts from the same idea as Andrej Karpathy's autoresearch: there, an agent edits one training file, trains for a fixed five minutes, checks a single metric and keeps or discards the change, about a hundred experiments a night. Our version runs on Weights & Biases: the model, the traces, the runs and the registry.

Each page is audited for accessibility with axe-core and timed twice: once on a practice split the agent can see, and once on a sealed held-out split it never sees. Both timings land in the Weave Evals tab, which is where our gates read them. That seal matters because an agent that keeps checking against the same test starts to learn the test. That is exactly the problem Blum and Hardt's Ladder and Dwork and colleagues' reusable holdout were built to solve, and one of our gates is a Ladder. A seal needs isolation, and W&B Sandboxes are built for exactly that: the agent's own code, kept out of process.

Autoresearch judges a whole run by one number. Scrutineer instead traces every failing page back to the one component that caused it, much as TextGrad sends feedback back to individual parts of a compound AI system. That only works because W&B Weave traces every step: build, audit, replay, blame and gate. There are ten components: retrieval, the model, sampling, verification, curriculum, the proposer, budget, audit, memory and deploy. Each one gets its own W&B run, so the credit it earns is a curve you can open, not a number buried in a log. Curriculum picks practice tasks, like Voyager's automatic curriculum, and memory records findings for next time, the way Reflexion keeps its reflections. Every generation, memory writes its debrief as a marimo notebook: something you can run, not just read.

The change then has to clear a set of gates, including size, novelty, evidence, regression, a check that both splits agree, and cost. The last gate is a marimo notebook that has to reproduce the promotion decision; if it can't, the change is refused.
It is kept only if every gate passes, and every kept change is written to a signed ledger, our version of autoresearch's experiment log and the Darwin Gödel Machine's archive of agents. Every generation, kept or refused, is also reported to the ARIA board.

On the car, wings are retrieval, the floor is verification and tyre compound is sampling, so a kept change visibly rebuilds the car. Each version is registered in W&B Registry under an alias, so the car that raced is the car that was promoted.
Where the car sits on the lap shows how far the current run has got. From Inference to Weave, that's the Weights & Biases stack under the car, and W&B has been part of CoreWeave since 2025.
